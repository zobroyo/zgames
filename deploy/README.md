# Z Games on the black box

**https://game.z-chat.men** is served from the black box by a small Node
server on port **8722**. Accounts, OAuth sessions and any persistent state live
on Supabase; the box only serves the site and a local mirror of the CrazyGames
catalog. The Cloudflare tunnel runs in Docker on the same machine.

## What runs where

| Path / unit | What it is |
| --- | --- |
| `/srv/zgames/server.mjs` | HTTP server (`zgames.service`), listens on `0.0.0.0:8722` |
| `/srv/zgames/site/` | Static site root (`ROOT`), including `catalog.json` (`CATALOG`) |
| `/srv/zgames/mirror/` | Mirrored game assets (`MIRROR_DIR`) |
| `/srv/zgames/tools/mirror.mjs` | Catalog mirror tool (`zgames-mirror.service`) |
| `/srv/zgames/state/` | Runtime state |
| `/srv/zgames/session-secret` | Session signing secret, root:root 0600, generated by `install.sh` |

Environment (`zgames.service`): `PORT=8722`, Supabase
`https://dwstivxwyqdogzgxnidm.supabase.co`, OAuth client
`6122c80c-02a1-47fb-9a2f-17dba8403fe1`, redirect
`https://game.z-chat.men/auth/callback`.

## Cloudflare tunnel (Docker)

```
docker run -d --name zgames-tunnel --restart unless-stopped --network host \
  cloudflare/cloudflared:latest tunnel --no-autoupdate run --token <TOKEN>
```

Dashboard ingress: `game.z-chat.men -> http://localhost:8722`.

## Mirror timer and resume behavior

`zgames-mirror.timer` runs `zgames-mirror.service` 5 minutes after boot and
every 6 hours (`Persistent=true`, so a run missed while the box was off happens
after the next boot). The oneshot service mirrors up to 2000 games with 6
concurrent downloads into `/srv/zgames/mirror` and refreshes
`/srv/zgames/site/catalog.json`.

Runs are resumable: assets already present in `MIRROR_DIR` are skipped, so an
interrupted run (timeout, reboot, network loss) simply continues where it left
off on the next tick. One run at a time; the app keeps serving the existing
mirror while a refresh is in progress.

## Manual operations

```bash
systemctl start zgames-mirror.service     # mirror now instead of waiting
systemctl status zgames-mirror.timer      # is the timer active?
journalctl -u zgames-mirror.service -f    # watch a mirror run
journalctl -u zgames.service -f           # app logs
systemctl restart zgames.service          # restart the site
curl -s http://127.0.0.1:8722/healthz     # local health check
```

Fresh install (idempotent, run as root from the repo checkout):

```bash
sudo bash /srv/zgames/src/deploy/install.sh
```

It creates `/srv/zgames/{site,mirror,tools,state}`, copies `server.mjs`,
`tools/mirror.mjs` and `site/` from the parent of `deploy/`, generates
`session-secret` if missing, installs the units, enables the service + timer
and starts them.

## Sandbox / security notes

Everything runs as the dedicated `zchat` system user (nologin, home
`/srv/zchat`) with the same systemd sandbox as the chat app:

| Protection | Effect |
| --- | --- |
| `User=zchat` / `Group=zchat` | no root, no sudo, no login shell |
| `ProtectHome=yes` | `/home`, `/root` and `/run/user` are invisible |
| `ProtectSystem=strict` + `ReadWritePaths=/srv/zgames` | rest of the filesystem is read-only |
| `NoNewPrivileges`, `CapabilityBoundingSet=`, `AmbientCapabilities=` | cannot gain or keep privileges |
| `PrivateTmp`, `ProtectKernel*`, `ProtectControlGroups` | private `/tmp`, kernel and cgroup protection |
| `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX` | only normal network sockets |
| `RestrictSUIDSGID`, `LockPersonality`, `ProtectProc=invisible`, `ProcSubset=pid` | no setuid/setgid, no personality changes, cannot see other processes |

`session-secret` is root-owned 0600 and is read by systemd (PID 1) before
privileges are dropped; the app itself never needs to read it. The mirror can
reach the internet (CrazyGames CDN) and the site can reach Supabase; neither
can touch the host.
